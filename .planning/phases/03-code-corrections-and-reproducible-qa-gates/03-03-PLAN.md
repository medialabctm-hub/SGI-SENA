# 03-03 — Límites públicos seguros

## Objetivo

Aplicar límites independientes y no enumerables al autoservicio, usando IP y
un identificador normalizado/hashado donde el body ya está disponible. No se
inventará una identidad de kiosko: `registro-externo` queda explícitamente
parcial/BLOCKED para API key, firma, cuota diaria y staging hasta decisión de
política.

## Tareas

1. Crear limitadores con respuesta `429` consistente y claves que no almacenen
   documentos/placas en claro ni logs.
2. Aplicarlos antes del controlador de autoservicio sin reemplazar el gate de
   clase, roster, transacción o idempotencia.
3. Cubrir IP, identificador repetido y no enumeración; dejar pruebas o nota
   explícita sobre la superficie multipart de `registro-externo`.

## Verificación

```text
npm test --prefix backend -- --runInBand tests/middleware/rateLimiter.test.js tests/routes/equiposRoutes.test.js
git diff --check
```

No se ejecuta denegación de servicio ni se prueban datos reales.
