# 03-02 — Readiness y DDL fuera del request path

## Objetivo

Mantener `ensureAutoservicioSchema` en el boot/comando administrativo y hacer
que una petición pública falle cerrada con `503` si el readiness no está listo.
Este plan no extrae todavía las 4.653 líneas del controlador; realiza el corte
incremental seguro que puede verificarse sin cambiar contratos HTTP.

## Tareas

1. Retirar la invocación de migración/`INFORMATION_SCHEMA` de
   `iniciarUsoAutoservicio` y exponer un guard de readiness estable para ese
   request path.
2. Conservar la migración en `server.js`, mantener `/health` como fuente de
   readiness y evitar duplicar autorización o alterar los estados `404/409`.
3. Ajustar pruebas para demostrar que la ruta no ejecuta `CREATE`, `ALTER` ni
   `INFORMATION_SCHEMA`, que devuelve `503` antes de abrir transacción y que el
   claim listo conserva idempotencia/rollback.

## Verificación

```text
npm test --prefix backend -- --runInBand tests/controllers/equiposAssignmentAutoservicio.test.js tests/controllers/equiposAutoservicioAmbiente.integration.test.js tests/routes/health.test.js
rg -n "ensureAutoservicioSchema|INFORMATION_SCHEMA|CREATE TABLE|ALTER TABLE" backend/src/controller/equiposController.js backend/tests/controllers
git diff --check
```

MySQL concurrente real se reporta por separado; los mocks no prueban el
despliegue.
