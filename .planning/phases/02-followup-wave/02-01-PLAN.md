# 02-01 — MDL-133 + MDL-132: uploads privados y contrato JWT/login-placa

## Objetivo

Reducir la exposición real de fotografías privadas y cerrar el contrato de
autenticación heredado con cambios verticales, pequeños y probables localmente.
Se preservan las URLs actuales de las imágenes para no romper consumidores: el
path sigue siendo el mismo, pero deja de existir un montaje estático y pasa por
autenticación, autorización, metadata y resolución segura.

## Issues seleccionadas y límites

- **MDL-133 (prioridad de seguridad):** restringir `/uploads/perfiles` y
  `/uploads/ambientes` sin retirar el flujo legítimo. No se diseña un nuevo
  storage remoto ni se cambia el modelo de roles: perfiles permiten propietario
  o `users:view_detail`; ambientes usan el permiso existente `ambientes:view`.
- **MDL-132 (hardening acotado):** mantener `cookie-parser` deliberadamente sin
  firma porque la cookie contiene un JWT firmado y no se consume
  `req.signedCookies`; se elimina la exigencia/configuración muerta de
  `COOKIE_SECRET`. Se fijan HS256/issuer/audience en JwtService y se agrega
  Zod a `login-placa` sin inventar una identidad de kiosko ni alterar el flujo
  de escritorio que recibe el token en el body.

## Dependencias y riesgos

- Depende de los contratos de sesión de MDL-127: `sgi_session` sigue siendo
  httpOnly y el navegador sigue usando `credentials: include`.
- El handler privado debe consultar metadata antes de `sendFile`; un archivo
  existente sin fila autorizada se trata como 404.
- Un `users:view_detail` revocado en BD debe negar perfiles ajenos; no se debe
  confiar solo en `req.user.rol` salvo el bypass de Administrador ya adoptado.
- Activar issuer/audience invalida tokens emitidos antes del cambio; el login
  normal y `login-placa` emiten nuevos tokens. Esto queda como riesgo de
  despliegue/documentación, no se agrega una compatibilidad insegura.
- No se ejecutarán MySQL real, Docker, Railway, servicios externos, navegador,
  staging ni UAT; cualquier evidencia de esos entornos queda BLOCKED/humana.

## Tareas

### 1. Implementar MDL-133

- Retirar los dos `express.static` de `backend/src/app.js` y registrar handlers
  GET autenticados para conservar `/uploads/perfiles/:filename` y
  `/uploads/ambientes/:filename`.
- Resolver el propietario/ambiente usando consultas parametrizadas sobre
  `Usuarios.foto_perfil` e `Imagenes_Ambiente.ruta_imagen`.
- Confinar cualquier archivo a su raíz esperada; rechazar `..`, separadores,
  rutas absolutas, nombres inválidos, symlinks y archivos que no sean regulares.
  Responder 404 genérico para no enumerar recursos no autorizados y enviar
  `Cache-Control: private, no-store`.
- Añadir pruebas de ruta pública eliminada, 401/404/permiso/propietario,
  traversal y symlink mediante fixtures temporales o mocks seguros.

### 2. Implementar MDL-132

- Extender JwtService de forma compatible con sus constructores de test para
  fijar HS256 y verificar `issuer`, `audience` y expiración.
- Pasar `config.jwt` al registro DI y mantener los defaults ya existentes
  (`gse-app`, `gse-users`); no aceptar un algoritmo elegido por el token.
- Crear `loginPlacaSchema` con límites para cedula/placa y contraseña no vacía,
  aplicarlo después de `authLimiter`, y conservar la validación defensiva del
  controlador.
- Eliminar `COOKIE_SECRET` de variables requeridas/ejemplos/documentación
  solo donde su uso real está ausente; dejar una nota explícita de que JWT y
  cookies son contratos distintos.
- Añadir pruebas negativas de issuer/audience/algoritmo/expiración, body
  inválido y presencia de `validate(loginPlacaSchema)` en la ruta.

### 3. Verificar, documentar y entregar

- Ejecutar suites backend focalizadas, ESLint de archivos tocados y
  `git diff --check`; usar el package manager/scripts existentes del backend.
- Si se requiere una comprobación frontend por el contrato de URL, usar `pnpm`
  y solo una suite/build focal; no ejecutar la suite frontend completa agrupada.
- Revisar diff para excluir `package-lock.json`, secretos, servicios reales y
  cambios no relacionados.
- Crear SUMMARY y VERIFICATION con PASS/FAIL/BLOCKED, riesgos residuales y
  issues no seleccionadas.
- Hacer un commit atómico por issue (`MDL-133` y `MDL-132`) sin push; si una
  unidad no alcanza evidencia suficiente, no marcarla como cerrada.
